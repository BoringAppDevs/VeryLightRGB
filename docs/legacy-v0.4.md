# RGB Tray 0.4

Легка Windows x64 / C# WinForms програма для RGB. Нативно підтримує **MSI MAG B850M MORTAR WIFI (MS-7E61)** та **Gainward RTX 5080 Phoenix** без SignalRGB, OpenRGB або драйвера ядра. Додатковий локальний OpenRGB SDK backend призначений для іншого сумісного обладнання.

## Меню

- **Підсвітка**: «Усе разом» або окремий вибраний пристрій. HEX / палітра, яскравість, ефект і попередній перегляд. Прапорець спільного стилю синхронізує пристрій; зняття дозволяє власні колір та анімацію. Незалежний стиль запам’ятовується. Загальна кнопка живлення вимикає також незалежні зони.
- **Кількість діодів** видно одразу. В «Усе разом» вона задає довжину всіх вибраних виходів із регульованою довжиною; для окремого ARGB-виходу — лише його довжину. Напрямок, зміщення й назва розміщені у додаткових параметрах. GPU має одну зону, її кількість не змінюється.
- **Пристрої**: доступні контролери / виходи. Прапорцями вибираються потрібні; лише вони потрапляють на головну вкладку. «Підсвітити вибраний» дає білий імпульс і повертає поточний стиль керованої зони; для невибраного виходу залишає темний колір. «Лише цей ARGB-хедер» прибирає інші MSI-виходи, зберігаючи GPU.
- **Система**: backend, SDK-порт, FPS, автозапуск і журнал.
- Tray: швидкий спільний колір / ефект, живлення, відкриття вікна й вихід. Хрестик ховає вікно. **Профілі видалені**, налаштування зберігаються автоматично.

## Хедери та LED

Три MSI-виходи — це доступні ARGB-роз’єми, **не три знайдені вентилятори**. На цьому ПК зайнятий **ARGB 1 (індекс протоколу 0)** із трьома паралельно підключеними Thermalright TL-K12. Користувач визначив його за червоним кольором у тесті трьох виходів. Вентилятори повторюють один сигнал, тому незалежне керування ними неможливе.

Для звичайного ARGB / TL-K12 використаний протокол не дає надійної ознаки підключеного кабелю або фізичної кількості діодів. HID підтверджує запис і для порожнього виходу. Нові MSI-виходи початково не вибрані. Існуючий вибір зберігається: якщо раніше були вибрані всі три, потрібно залишити фактичний у «Пристрої».

Для TL-K12 початково **12 LED**, відповідність фізично підтверджена користувачем. [Thermalright](https://www.thermalright.com/product/tl-k12/) не вказує кількість; 12 також називає [власник після звернення до підтримки](https://www.reddit.com/r/Thermalright/comments/1iz3gus/comment/mg8mee3/). Це ручне калібрування. Нативна програма підтримує 1–120 адрес на вихід; це не електричний ліміт роз’єму.

Невідомий вихід визначається пробним підсвічуванням. CLI `--map-headers` ставить приглушені кольори: ARGB 1 червоний, 2 зелений, 3 синій. Налаштування, GPU та сторонні зони не змінюються. Після визначення потрібно вибрати хедер та застосувати звичайний стиль. Це візуальний тест, а не автоматичне визначення.

## Ефекти

| Ефект | Поведінка |
|---|---|
| Сталий колір | Апаратний колір; після запису немає циклу кадрів або відкритої сесії |
| По черзі | Плавне заповнення, пауза, згасання по одному в тому самому порядку |
| Темний блок по колу | Плавний рух темної ділянки; початкова ширина 4, регулюється |
| Дихання | Плавна зміна яскравості |
| Веселка | Без параметрів: яскравість 50%, оберт за 12 секунд |
| Перехід двох кольорів | Плавне чергування основного та другого кольору |

На GPU темний блок дає сталий колір, а «По черзі» змінює яскравість цілої зони. Інші ефекти також працюють на цілу GPU-зону. Один спільний годинник, 10–60 FPS (початково 30); однакові кадри не передаються. Сталі зони не переписуються через анімацію сусідніх. При приховуванні вікна зупиняється попередній перегляд. Вихід з анімації залишає сталий базовий колір; після resume пристрої знаходяться заново.

## Інші ПК

Нативна сумісність обмежена перевіреними моделями й точними USB / PCI ID, без прив’язки до унікального серійного номера цього ПК. Інша MSI-плата чи інша GPU автоматично не підтримуються. Підтримувані плата та GPU можуть працювати окремо.

Для іншого обладнання налаштуй [OpenRGB](https://openrgb.org/), довжини зон та його SDK-сервер; вибери OpenRGB у «Система». RGB Tray підключається **лише до 127.0.0.1**, початковий порт 6742. Потрібен SDK protocol 3+; клієнт узгоджує формат 3. Довжини SDK-зон лише для читання. Custom mode може впливати на весь контролер, включно з невибраними зонами. Сумісність залежить від OpenRGB. На реальному сторонньому обладнанні backend ще не перевірений; перевірено обмін із тестовим TCP-сервером.

## Збірка, запуск і тести

Потрібні Windows x64, .NET 8 Desktop Runtime x64; для збірки — .NET 8 SDK.

```powershell
.\scripts\build.ps1
# Завершити запущений екземпляр перед оновленням:
& "$env:LOCALAPPDATA\Programs\RgbTray\RgbTray.exe" --exit
.\scripts\install.ps1

dotnet run --project tests/RgbTray.Tests -c Release
# Реально змінює світло; спочатку завершити RGB Tray:
dotnet run --project tests/RgbTray.Tests -c Release -- --hardware-effects
.\scripts\verify-hardware.ps1
```

Встановлення: `%LOCALAPPDATA%\Programs\RgbTray\RgbTray.exe`, ярлик у меню Пуск, автозапуск поточного користувача. SignalRGB / launcher закриваються, його автозапуск вимикається, служби не змінюються. Початкові записи збережені в `%LOCALAPPDATA%\RgbTray\integration-backup.json`. Для повернення: вийти з RGB Tray та запустити `scripts\restore-signalrgb.ps1`.

Налаштування й журнал: `%LOCALAPPDATA%\RgbTray\settings.json`, `rgbtray.log`. JSON записується атомарно, журнал обмежений 512 КБ плюс попередня копія. Пошкоджений JSON показує помилку. Налаштування 0.3 читаються; старе поле Profiles ігнорується й більше не зберігається.

## CLI

```powershell
.\artifacts\RgbTray\RgbTray.exe --tray
.\artifacts\RgbTray\RgbTray.exe --set '#204060' --output local\apply.json
.\artifacts\RgbTray\RgbTray.exe --off --output local\off.json
.\artifacts\RgbTray\RgbTray.exe --diagnose --output local\diagnostics.json
.\artifacts\RgbTray\RgbTray.exe --test-effect --output local\effect-test.json
.\artifacts\RgbTray\RgbTray.exe --map-headers --output local\header-map.json
```

CLI не зберігає налаштування. Set / off працюють лише з вибраними виходами. Test-effect запускає поточний стиль на 6 секунд. Diagnose лише читає; нативний діагностичний CLI потребує обох перевірених контролерів. Для Windows-процесу потрібно чекати завершення (`Start-Process -Wait -PassThru`). Код виходу: 0 успіх, 1 помилка запуску / конфлікт, 2 помилка пристрою. Жива анімація утримує mutex; перед CLI потрібно її зупинити або вийти з програми.

## Нативний протокол

- MSI: HID `0DB0:0076`, модель MS-7E61, серійний префікс моделі `7E61`. Config `0x50`, 290 байт; змінюється лише вибрана 16-байтова зона. Steady mode 2 / direct mode 9; RGB-кадр `0x51`, 727 байт. Інші зони зберігаються, flash-save завжди 0. Підтвердження config: до шести читань із паузою 15 мс без повторного запису. Post-frame читання на перевіреній прошивці може повертати report `0x50`. Це не зчитування фізичного стану LED.
- Gainward: NVAPI, PCI `10DE:2C02 / 10B0:F323`, внутрішній I²C port 1, 7-bit адреса `0x49`; RGB `6C/6D/6E`, mode `60`, control `E0`, brightness `6F`. Немає сканування шин, доступу до DDC або охолодження.
- Немає записів BIOS / firmware / flash. Нативний режим перевіряє конфлікти з SignalRGB, OpenRGB та відомими процесами Mystic Light; SDK-режим дозволяє OpenRGB. Mutex координує нашу програму, а не всі сторонні RGB-програми.

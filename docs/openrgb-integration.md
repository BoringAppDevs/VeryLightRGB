# OpenRGB — інтеграція і реальні перевірки

2026-11-01, Very Light RGB 1.0.1. Це доповнення до початкового [рев’ю native 1.0](review-native-v1.md).

## Що додано

В `third_party/openrgb` додані **самі архіви** офіційного OpenRGB 1.1 Windows x64 та його вихідного коду цього релізу, ліцензія, manifest із URL / SHA-256, інвентар runtime-файлів і список детекторів. Ці архіви не перебувають у `.gitignore`. Окремо додані `scripts/setup-openrgb.ps1`, `start-openrgb.ps1`, `stop-openrgb.ps1`; розпакований runtime і тестові конфігурації ігноруються.

Реліз: [OpenRGB 1.1](https://openrgb.org/releases.html), commit `8e16de27858cf2be6af54a33ce003df74cb9fd3e`, SDK server protocol 6. Клієнт узгоджує підтримуваний ним формат 3. OpenRGB лишається окремим процесом. Native-only ZIP не виріс на розмір Qt; `package-native.ps1 -WithOpenRgb` створює окремий комплект з OpenRGB та source archive.

Клієнт отримав:

- `--sdk-list --sdk-port PORT --output FILE`: read-only опис усіх контролерів, зон, режимів, меж довжини й кешу кольорів. Нульові зони також видимі в діагностиці.
- `--sdk-resize --sdk-port PORT --id STABLE_ZONE_ID --led-count N --output FILE`: явне setup-налаштування зони. Перевіряються наявність / однозначність ID, min/max і максимальні 4096 LED. Індекс береться зі свіжого каталогу; після запиту сесія інвалідується. Потрібні повторний список і Reload devices. Це не readback фактичної кількості LED і не автоматична операція звичайного запуску.
- opt-in тести `tests.exe --openrgb PORT` (читання) і `tests.exe --openrgb-hardware PORT` (точно перевірені MSI / Gainward, змінює світло й відновлює стан).

## Що знайшов справжній OpenRGB

| Обладнання | Результат |
|---|---|
| Gainward RTX 5080 Phoenix, PCI 10DE:2C02 / 10B0:F323 | Один контролер, одна зона `GPU Zone`, Direct підтримується |
| MSI B850M Mortar, USB 0DB0:0076 | Контролер `MSI MYSTIC LIGHT`; детектор `MSI Mystic Light X870` відповідає фактичному usage FF00/0001 |
| JARGB 1 | Початкова довжина 0; явно налаштовано 12 LED, після цього зона доступна нашому SDK backend |
| JAF / JARGB 2 / JARGB 3 | Не налаштовувалися, довжина 0; не вибиралися для анімації |
| Keychron Link, USB 3434:D030 | Dongle видно в HID, викликано штатний Keychron RGB QMK/ZMK detector; RGB-контролер у цьому підключенні / firmware не зареєстрований |
| Razer | Підключеного підтримуваного Razer у тесті немає; RGB-керування не перевірене |

Наявність Keychron Link не доводить відсутність RGB на самій клавіатурі: результат залежить від підключення, прошивки, відповіді клавіатури через dongle. Жодних змін firmware або вводу клавіш не виконувалося. Для наступної перевірки корисне пряме USB-підключення клавіатури з її точною моделлю. Не додавався випадковий VID/PID у native allowlist.

Нативний модуль цього проєкту знає, що зайнятий ARGB 1 має 12 LED із попереднього ручного калібрування. Stock OpenRGB цього не визначає сам. Його кількість зон / максимальні 240 адрес не є кількістю підключених вентиляторів або діодів.

## End-to-end перевірка

Реальний portable OpenRGB, не TCP-емулятор, спочатку з трьома цільовими детекторами; після створення повного registry-списку підтверджено, що увімкнені тільки MSI X870, конкретний Gainward 5080 Phoenix та Keychron RGB QMK/ZMK. Native агент на час тесту був завершений. OpenRGB не встановлювався системним installer, не додавався в автозапуск; PawnIO / elevation не змінювалися. Повідомлення про недоступні SMBus/PawnIO не завадило двом цільовим контролерам через USB HID / NVIDIA NVAPI.

| Перевірка | Доказ / результат |
|---|---|
| Офіційні архіви й runtime | SHA-256 обох архівів та кожного розпакованого файла збігається з manifest / inventory |
| Формат SDK | Сервер 6, клієнт 3; реальні описи обох контролерів розібрані |
| Setup JARGB 1 | Запит зміни довжини через stable zone ID; наступний незалежний список показав 12 LED |
| GPU колір #204060 | Після відправлення через SDK незалежне фізичне читання NVAPI-регістрів 6C/6D/6E дало 32/64/96 |
| MSI зона | Після SDK-запису фізичний HID readback підтвердив mode 9 та довжину 12 |
| Кеш кольорів OpenRGB | GPU #204060; MSI 12 кольорів #181818 після відповідного кадру |
| Анімація | 24 кадри темного блоку через реальний SDK; статична GPU зберегла фізичні регістри 32/64/96 |
| Off | GPU фізично читалася як 0/0/0; окремий master-off установленого тестового агента дав усі 13 кольорів чорними в OpenRGB |
| Відновлення після hardware-тесту | Повна попередня MSI-конфігурація readback збіглася; колір / режим / яскравість GPU відновлені |
| Повний Very Light RGB агент через SDK | Два успішні виходи: біле заповнення ARGB 1 та незалежна статична #64E6C6 GPU |
| Перезапуск сервера | Клієнт виявив disconnect, припинив анімаційні записи, зробив bounded reconnect; після нового сервера обидві зони відновилися. Конфігурація до / після повністю однакова |
| Присутність кешу | У журналі SDK-агента немає повторного hardware catalog refresh; при reconnect прочитані метадані сервера й переприв’язані поточні індекси |
| Репозиторні скрипти | Запуск із bundled runtime, збереження вже налаштованої зони, owned stop; NoDetect smoke повернув 0 контролерів |
| Повернення користувацького стану | SDK тестовий агент і OpenRGB завершені; native task знову керує двома виходами; конфігурація збіглася з snapshot до тестів |

Базовий набір після змін: **1269 assertions** без hardware. Повний набір із реальним OpenRGB: **1283 assertions**, із них 14 у реальній SDK-перевірці; підключено 2 контролери / 2 непорожні зони. Нативний hardware-набір також повторно пройдено після SDK-тестування: **1303 assertions**. Еталонні 432 кадри попередніх ефектів збережені. Фінальний SDK-тест повторено з репозиторним `start-openrgb.ps1 -Detection ThisPc` та незміненим релізним runtime.

RGB-регістри GPU є фізичним readback. Кольори в SDK controller description — кеш OpenRGB, а не читання світла. Для MSI фізично підтверджені режим / довжина та успішні HID-транзакції; кольори кожного окремого діода візуально за відсутності користувача не підтверджувалися.

## Ресурси з анімацією

Два одночасні заміри приблизно по 60,6 с, 16 logical CPU, меню закрите. Той самий білий fill 12 LED + статична GPU. Не встановлювався нижчий working set вручну.

| Процес | Середній working set | Private commit | CPU одного ядра | CPU всього ПК |
|---|---:|---:|---:|---:|
| Very Light RGB SDK-агент | 13,6 МіБ | 2,4 МіБ | 0,232% | 0,015% |
| OpenRGB 1.1, без GUI | 29,4 МіБ | 9,5 МіБ | 0,413% | 0,026% |
| Разом, проста сума | **43,0 МіБ** | **11,9 МіБ** | **0,645%** | **0,041%** |

Проста сума working set може двічі врахувати спільні сторінки; це консервативна сума двох процесів. Static / GUI / інше обладнання дадуть інші числа. Для native backend на цьому ПК раніше отримано приблизно 14,7–14,8 МіБ. Тому після тесту залишений **native**, OpenRGB не тримається у фоні без потреби.

Сирі локальні докази (не входять у release ZIP): `local/openrgb-real-devices-final.json`, `local/openrgb-physical-integration.json`, `local/openrgb-hardware-test-result.txt`, `local/openrgb-enabled-detectors.json`, `local/openrgb-resources-agent.json`, `local/openrgb-resources-server.json`, `local/sdk-restart-*.json`, `local/sdk-off-inspect.json`, `local/openrgb-native-restored.json`.

## Рев’ю змін

Розбір опису контролера тепер спільний для каталогу та inspect, із тими самими межами / перевіркою довжини. Порожні зони не стають керованими автоматично. Resize — явна CLI-команда із перевіркою stable identity та меж; звичайні discover / reconnect / frames resize не викликають. Session після resize відхиляє наступні записи зі старими довжинами. Тести покривають читання inspect, невідомий ID, перевищення max, відсутність запису при помилці та інвалідацію сесії.

Скрипти перевіряють контрольні суми, слухають тільки loopback, не замінюють чужий процес на зайнятому порту й не завершують довільний PID. У stop виправлено порівняння часу створення: PowerShell JSON може повернути DateTime замість рядка, тепер порівнюються UTC ticks. Синтаксис усіх PowerShell скриптів перевірений. Start/stop та повторний start з існуючою конфігурацією реально перевірені також у штатному Windows PowerShell 5.1; для case-sensitive detector keys використаний сумісний JSON reader, окремо від PowerShell 7.

OpenRGB може змінити режим цілого контролера через CustomMode / setup і має власний startup scan. Для hybrid потрібно вимкнути відповідні native детектори в OpenRGB. Не варто запускати два backend на одному контролері заради меншої пам’яті. `start-openrgb.ps1 -Detection Configured` зберігає обрані користувачем детектори й довжини; явні presets замінюють вибір.

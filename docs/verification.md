# Перевірка на ПК користувача

Дата: 1 листопада 2026 року, Europe/Budapest.

## Реальне обладнання

- MSI MAG B850M MORTAR WIFI (MS-7E61), USB HID `0DB0:0076`, feature report length 761.
- NVIDIA GeForce RTX 5080, Gainward subsystem `10B0:F323`; внутрішній I²C RGB-контролер `0x49` на GPU-порту 1.
- Фактична модель вентиляторів — **Thermalright TL-K12**, за уточненням користувача. У збереженому профілі SignalRGB були вибрані TL-S12 із 15 LED; цей профіль не є підтвердженням моделі чи реальної кількості діодів. Офіційна [специфікація TL-K12](https://www.thermalright.com/product/tl-k12/) вказує 5V/3Pin ARGB, але не кількість LED. Після пошуку знайдено [повідомлення власника про відповідь Thermalright: 12 LED](https://www.reddit.com/r/Thermalright/comments/1iz3gus/comment/mg8mee3/). Користувач виставив 12 і підтвердив кращу роботу; у v0.3 це початкове значення для нових налаштувань. Автоматичне фізичне вимірювання не проводилося. Реальна кількість фізичних вентиляторів через паралельний розгалужувач програмно не визначається.

## Пройдені перевірки

| Перевірка | Результат |
|---|---|
| Release build | Без помилок та попереджень |
| Автоматичні перевірки протоколу й налаштувань | Пройшли; обладнання не використовують |
| Прямий запис `#600000`, `#006000`, `#000060`, `#000000`, `#002466` | MSI та Gainward підтвердили значення читанням |
| Палітра у встановленому Windows-інтерфейсі | Вибрано м’ятний `#64E6C6`, збережено у settings.json |
| Кнопка вимкнення | Обидва контролери повернули RGB `0,0,0`; колір і яскравість у налаштуваннях збережено |
| Кнопка увімкнення | Відновила попередній колір |
| Яскравість 50% | RGB `50,115,99` для `#64E6C6`; підтверджено обома контролерами |
| Повторний запуск .exe | Залишився один процес, існуюче вікно відкрилося |
| Згортання | Вікно приховано, MainWindowHandle=0, процес залишився у tray |
| `--exit` | Процес завершився коректно |
| Повторний запуск із `--tray` | Колір і яскравість відновлено, вікно приховано |
| Встановлення | .exe у LocalAppData\Programs\RgbTray; ярлик RGB Tray у «Пуск» |
| Автозапуск | HKCU Run `RgbTray` містить встановлений .exe з `--tray`; попередній SignalRgb Run збережено у резервній копії та вимкнено |
| Конфлікт із SignalRGB | Запис відхилено, поки він був запущений; launcher довелося закрити перед основним процесом |

Повторна перевірка поточного кольору без змін обладнання:

```powershell
.\scripts\verify-hardware.ps1
```

## Ефект v0.2.0

Додано «По черзі · плавне заповнення»: 200 мс темряви → плавне додавання діодів → 350 мс повного світла → скидання. Початково 15 діодів, 180 мс на діод. GPU синхронно засвічує весь логотип, бо доступна одна RGB-зона.

Перевірено:

- Release build без помилок і попереджень.
- 1627 автоматичних перевірок без обладнання: межі й повторення циклу, збереження раніше ввімкнених діодів, проміжні рівні плавного переходу, синхронізація GPU, межі RGB-пакетів, збереження сторонніх зон, відсутність flash-save, міграція старих налаштувань.
- Додатковий запуск із `--hardware-effects`: 1646 перевірок разом із живим ефектом, виключенням конкуруючих операцій, зупинкою в чорний, негайним скасуванням до ініціалізації й повторною зупинкою. Після тестів збережений сталий колір відновлено й прочитано на MSI та Gainward.
- `--test-effect`: за 6 секунд виконано 155 повних обмінів кадрами з трьома ARGB-хедерами без помилок HID/NVAPI. Після тесту RGB `255,255,255` підтверджено на обох контролерах.
- MSI приймає direct-mode 9 і задану кількість діодів у report `0x50`. На post-frame GetFeature `0x51` прошивка повертає зональний report `0x50`; це явно враховано лише для post-frame читання. Звичайні конфігураційні читання й далі перевіряють точний report ID. Фізичний колір окремих LED через ці відповіді прочитати не можна.
- Під час живого ефекту окрема CLI-діагностика відхиляється через mutex; після зупинки mutex звільняється.
- Запуск програми зі збереженим ефектом і `Enabled=false`: прочитано чорний на всіх трьох MSI-зонах та GPU.
- Запуск з ефектом і нульовою яскравістю: також чорний, цикл кадрів не запускається.
- Запуск із `Effect=Solid`: прочитано сталий білий на MSI та GPU.
- Після перевірок відновлено профіль ефекту й запущено встановлену програму з `--tray`. У журналі є успішний запуск ефекту; працює один процес v0.2.0.

Оновлений .exe: **216 660 байтів**. Один 20-секундний замір під час анімації: **71,9 МБ working set**, **22,8 МБ private bytes**, **484,375 мс CPU-часу**, тобто приблизно **2,42% одного ядра** або **0,15% загальної потужності 16 логічних процесорів**. Журнал за цей час не зріс. Значення є одним заміром, а не гарантованими лімітами.

UI Automation розпізнала новий режим, 15 діодів і 180 мс у встановленому інтерфейсі. Візуальну перевірку нового вікна й натискання нових контролів завершити не вдалося: захоплення було чорним, активація повернула `GetCursorPos failed: Access is denied (0x80070005)`. Далі UI-введення не виконувалося. Перевірки зупинки й режимів виконано через тести та перезапуск із відповідними профілями.

## Зміна циклу v0.2.1

За уточненням користувача прибрано одночасне скидання світла після заповнення. Тепер після 350 мс повного світла діоди плавно гаснуть по одному в тому ж порядку. Після останнього діода — 200 мс темряви та нове заповнення. Для 15 діодів і 180 мс на діод повний цикл становить 5,95 с. GPU плавно зменшує яскравість разом із часткою ввімкнених діодів.

Пройшли 1754 перевірки без обладнання, включно з відсутністю різкого скидання, порядком згасання, незростанням яскравості під час згасання, зміною лише одного LED за крок, повторенням нового циклу та плавним згасанням GPU. Release build без попереджень і помилок.

Три послідовні шестисекундні запуски на обладнанні виконали 163, 159 і 158 повних обмінів кадрами. Після них сталий білий перевірено читанням MSI та GPU. Під час першої попередньої спроби ініціалізація один раз не підтвердила режим одразу після запису; додано обмежене очікування підтвердження конфігурації (до шести читань із паузою 15 мс) перед наступним записом, без повторного надсилання конфігурацій. Три фінальні запуски пройшли без цієї помилки. Встановлено й запущено один процес v0.2.1; колір, яскравість, кількість діодів і час кроку збережено.

## Режим «По колу · 4 темні діоди», v0.3.0

Додано окремий режим `CircularDarkBand=2`, збережено `Solid=0` та `SequentialFill=1`. Чотири суміжні адреси утворюють темний блок. Він зміщується на один LED за крок; попередній діод плавно засвічується, наступний плавно гасне. Перехід через останню адресу до першої безперервний; сумарна яскравість зберігається навіть при округленні RGB. Логотип GPU світиться сталим вибраним кольором. Цей режим не припускає неперевірену фізичну кількість секцій; параметр довжини підтримує і 12, і 16 адрес.

Пройшли 7102 перевірки без обладнання: циклічне перенесення темного блоку, точна кількість вимкнених адрес на цілих кроках, плавне перехресне згасання крайніх діодів, сталість усіх трьох каналів сумарної яскравості, безперервність стику циклу, межі довжини та сумісність збережених налаштувань. Разом із додатковим живим тестом нового режиму — 7128 перевірок. Перевірено роботу кадрів, захоплення та звільнення mutex, зупинку в чорний і відновлення сталого кольору після тестів.

Шестисекундний тест нового режиму на реальному обладнанні: 180 повних обмінів кадрами, 12 LED, 200 мс на крок; після завершення прочитано збережений RGB `198,92,255` на MSI та GPU. Встановлено й запущено v0.3.0, один процес. Після перезапуску збережені поточні налаштування користувача: `#C65CFF`, 100%, 12 LED, 200 мс на крок, ефект `CircularDarkBand`.

Користувач наживо підтвердив, що темний блок із чотирьох діодів плавно рухається по колу, а решта підсвітки залишається ввімкненою: «Так, саме так».

## Ресурси v0.1 · сталий колір

Початкова single-file framework-dependent збірка: **199 764 байти**. Потребує встановленого .NET 8 Desktop Runtime x64; розмір runtime не входить у розмір .exe.

Один замір після згортання у tray, 20 секунд:

- Working set: **67,1 МБ**.
- Private bytes: **17,8 МБ**.
- Приріст CPU-часу: **0 мс** за точністю лічильника; це короткий замір, а не гарантія абсолютного нульового навантаження.
- Приріст журналу: **0 байтів**. У коді після успішного запису немає активного таймера або циклу HID/I²C.

До зупинки SignalRGB один попередній замір основного процесу показував приблизно 503 МБ working set і 1034 МБ private bytes. Це орієнтовне порівняння окремих знімків, без підсумовування допоміжних процесів.

## Межі перевірки

Користувач підтвердив коректну роботу сталого кольору у v0.1 та наживо підтвердив поступове заповнення окремих діодів ефекту v0.2. Програмно перевірено алгоритм, direct-mode та обмін кадрами. Повний вихід / повторний вхід у Windows, перезавантаження та реальний sleep/resume не виконувалися, щоб не переривати роботу ПК. Автозапуск перевірено за реєстром і запуском встановленого .exe з тим самим `--tray`; обробник resume реалізовано, але реальне пробудження ще треба перевірити. Відновлення SignalRGB-скриптом не запускалося після фінального встановлення.

Останній стан: v0.3.0 працює в tray, ефект «По колу · 4 темні діоди», колір `#C65CFF`, яскравість 100%, 12 діодів, 200 мс на крок, світло увімкнене. SignalRGB та його launcher зупинені; його Windows-служба не змінювалася.

Дампи контролерів, знімки ресурсів і результати команд збережені лише в локальній директорії `local/`, що виключена через .gitignore. Серійний номер контролера у цьому документі не публікується.

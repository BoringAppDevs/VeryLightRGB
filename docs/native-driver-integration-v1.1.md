# Native Auto / Offline — 1.1.0

Включене driver-core підключене до основного tray-агента, меню, налаштувань та інсталяції. Backend 0 — **Native · Auto / Offline**. SDK-сервер для нього не запускається.

## Поведінка

* Перше налаштування / Reload devices зіставляє поточні USB/HID endpoints із скомпільованими детекторами. Для додаткових GPU використовуються PCI/subsystem ID дисплейних адаптерів. Запускаються тільки відповідні детектори. Загальні RAM/SMBus, мережеві та довільні custom detectors автоматично не вмикаються.
* Перевірені MSI/Gainward виключаються з додаткового пошуку й залишаються на малих прямих модулях.
* Виходи з’являються у звичайному Devices, а стилі працюють у Lighting: незалежні кольори, яскравість, усі програмні ефекти, off/on, identify, ручна довжина там, де її дозволяє драйвер.
* Каталог кешується в конфігурації. Підключення після зміни кольору / перезапуску worker відкриває відомі детектори та шляхи. Звичайне редагування кольору не запускає повний rescan.
* Ідентичність включає дані контролера й конкретну зону, а не порядковий серверний індекс. Старі schema 2/3 та налаштування кольору/мови збережені.
* Статичні driver-виходи утримують дочірній worker для апаратного keepalive. Engine перевіряє процес та наявність HID endpoints. Після збою виконується обмежене перепідключення з кешу. Якщо додаткові виходи не вибрані, worker не залишається працювати.
* Hybrid лишається MSI/Gainward + SDK; driver-core використовується у Native Auto, щоб не додавати подвійне володіння SDK-контролерами.

`AppliedRevision` у status відділяє збережену конфігурацію від завершеного апаратного застосування. У разі помилки status містить її для конкретного виходу.

## Перевірки

* **1370 software assertions**, включно зі справжнім прихованим дочірнім процесом і контролером у пам’яті. Перевірено конфігураційний roundtrip, маршрутизацію двох зон, незалежність статичної зони від анімації іншої, відмову на короткий кадр і відновлення JSONL після помилки.
* **1404 assertions** із opt-in native hardware suite: MSI/Gainward, readback та відновлення попередніх значень.
* Installed agent **1.1.0**: реальний Reload знайшов 7 виходів — три MSI headers, GPU та **Razer Basilisk V3 Pro Wireless / Scroll Wheel (1 LED), Logo (1 LED), LED Strip (11 LED)**. Усі п’ять тоді вибраних виходів прийняли ефекти, reload завершився без приміток.
* `scripts/verify-native-integration.ps1`: успішний реальний прогін із **22 секундами** статичного режиму (понад keepalive-інтервал), різними кольорами трьох Razer-зон, відсутністю animation-loop, off/on, контрольованим завершенням тільки власного worker, повторним підключенням і нульовою кількістю TCP connections. `finally` точно повернув повну початкову конфігурацію, включно з вибором зон. Звіт збережено в `local/native-live-check-d242196cfefe42f699fe7d0bb9daec7b/report.json` і не входить у portable-пакет.

USB/API success і кольори в програмному кеші не є фізичним optical readback усіх діодів Razer. Автоматичної гарантії для решти 2144 detector registrations немає. Непідтримувана firmware не стає сумісною від підстановки ID.

## Комплект

Папка `native-drivers` встановлюється та пакується разом з основним EXE: Qt-free core, transport DLL, модулі, база, ліцензії, оригінальні архіви й джерела bridge. На цьому ПК є потрібний Microsoft Visual C++ x64 runtime для HIDAPI/libusb. Скрипти не встановлювали kernel drivers і не змінювали firmware.

Механізм батьківського PID дозволяє дочірньому worker співіснувати зі своїм агентом/меню, зберігаючи блокування сторонніх RGB-програм. Pipe I/O обмежене за розміром і часом; успадковуються тільки три stdio handles. Kill-on-close job завершує worker при виході/збої агента.

Інсталятор зберігає живу конфігурацію та закриває лише меню того самого EXE після штатного запиту виходу background-агенту. Поточний вибір виходів користувача не замінюється тестовими профілями.

# Very Light RGB 1.0 — рев’ю та перевірки

Дата: 2026-11-01. Це власне код-рев’ю реалізації, не незалежний аудит. Стан: native версія зібрана, встановлена та керує MSI · ARGB 1 і Gainward RTX 5080 Phoenix. Старий RGB Tray збережений, його задача автозапуску вимкнена.

## Результат

Замість резидентного C# / WinForms UI використано C++20 / Win32 tray-агент і окремий текстовий процес меню. Шість ефектів, загальні / незалежні стилі, 12 LED на фактичному хедері, master off, автозапуск та збереження кольорів перенесені. Назв вентиляторів і профілів у native UI / конфігурації немає. Кількість LED видима в основному меню; у веселки немає параметрів кольору, яскравості або швидкості.

Поточні незалежні стилі збережені: ARGB 1 — білий, яскравість 15%, «По черзі», 12 LED; GPU — #64E6C6, 30%, статичний. ARGB 2/3 доступні як фізичні роз’єми, але не керовані. Це не ознака трьох підключених груп вентиляторів. У звичайному ARGB немає підтвердженого механізму визначення кабелю / кількості LED.

## Що перевірено у коді та виправлено

- **Пам’ять і фонова робота.** Статичний режим не має циклу кадрів, відкритої NVAPI-сесії або опитування UI. Анімація працює через waitable timer з низьким пріоритетом worker; однакові кадри пропускаються. Статична GPU не переписується через анімацію хедера. Немає глобального `timeBeginPeriod`, busy loop, резидентного console host або GUI framework. Нативні кадри використовують готові буфери.
- **Протоколи.** Точні USB / PCI allowlist, перевірка моделі плати та довжини HID feature report. Тільки вибрана MSI-зона; flash-прапорець завжди 0. Немає загального сканування I²C, установки kernel driver або зміни firmware. NVAPI завантажується тільки із системного каталогу. У холодній GPU-сесії додано bounded readback-повтори без повторного запису кольору; те саме для MSI-конфігурації.
- **Анімації.** Збережено поведінку попередньої версії, зокрема округлення на великих SDK-зонах, вимкнення master power для незалежних стилів, фіксовані параметри веселки й поведінку однозонної GPU.
- **Каталог.** Кеш із перевіркою схеми / розмірів. Нові порожні MSI-хедери не вибираються автоматично. При звичайному запуску не запускається повний каталогізаційний probe. Відомі USB endpoints шукаються за ID, SDK-індекси переприв’язуються до SHA-256 ідентичності метаданих. Перестановка індексів не спрямовує колір у випадкову зону. Неоднозначні ідентичності відхиляються. Зміна списку OpenRGB інвалідує TCP-сесію. Помилки початкового SDK-з’єднання тепер показуються та мають обмежені повтори.
- **Власність контролерів.** Виявлення конфліктних RGB-процесів. Hybrid перевіряє також тип SDK-контролера, а не лише редаговану назву: материнські плати / GPU не повинні перетинатися з native. Одна hardware lease координує стару й нову програму. Це не замінює вимкнення відповідних детекторів у OpenRGB.
- **IPC / конфігурація.** Pipe тільки локальний, ACL поточного користувача та SYSTEM, розмір JSON до 2 МіБ, вкладеність до 32, timeout / cancellation, ACK перед закриттям. Застаріла revision відхиляється. Налаштування записуються атомарно. При оновленні installer зберігає живу конфігурацію через IPC, чекає initial apply, повторює міграцію при зміні revision і перевіряє ключові параметри перед позначенням завершення.
- **Запуск і відновлення.** Задача запускає інтерактивний процес поточного користувача без elevation, після logon +10 с, з явною папкою даних і без execution time limit. Перевірка показала, що одного `RestartOnFailure` недостатньо для примусово завершеного процесу. Додані event triggers для власної fatal-події та Application Error точного EXE-шляху. Фатальний збій worker завершує агент із кодом помилки; звичайні помилки обладнання проходять обмежені повторні підключення.
- **Меню.** Реальний Unicode console buffer, нормальна палітра / HEX та numeric input, клавіші за virtual-key для української розкладки. Потенційні escape/control-послідовності із назв SDK видаляються. Закриття меню завершує лише TUI; повторне відкриття не створює другого агента. Вихід із tray завершує світловий worker.
- **Поставка.** Переносний компілятор і JSON закріплені за версіями / SHA-256. У EXE немає CLR / Qt / Python DLL. Ліцензії JSON та C++ runtime постачаються окремо. Старі C# файли й налаштування не видалені.

## Фактичні перевірки

| Перевірка | Результат |
|---|---|
| Native build `-O2 -Wall -Wextra -Werror` | Пройдено |
| Звичайний набір | **1264 assertions**, без RGB hardware |
| Повний opt-in набір на реальному MSI / GPU | **1298 assertions**, попередній стан відновлено |
| Еталонні кадри шести ефектів C# | **432 кадри**, поканально ідентичні |
| Native MSI / GPU | Різні кольори, readback, 24 анімаційні кадри, black/off, невибрані MSI-зони не змінені |
| Master off / on у встановленому агенті | Зупинка анімації, обидва записи успішні, стилі відновлені без змін |
| OpenRGB SDK test server | Fragmentation, invalid framing, reordered indices, notifications, disconnect, повтори, статичні виходи, stale revision |
| Справжній OpenRGB 1.1 | Локальний SDK server protocol **6**, узгоджено формат **3**, каталог порожній; `--nodetect` — обладнання не сканувалось |
| Реальний tray-шлях запуску меню | `CREATE_NEW_CONSOLE`, назва та Unicode frame підтверджені читанням власного console buffer |

| Задача Планувальника | Ручний запуск зареєстрованої задачі, правильні два виходи / кольори, конфігурація збережена на диску в контексті агента |
| Контрольований збій | PID 3248 → 2040, restart приблизно за **6 с**, конфігурація до / після повністю однакова |
| Звичайний вихід | Через 7 с процес лишався зупиненим; помилкового recovery не було |
| Installer upgrade | Успішний, поточні стилі не змінені; SHA-256 встановленого EXE збігається зі збіркою |
| Фінальна збірка, повтор recovery | PID 29352 → 15492, обидва виходи успішні, повна конфігурація збережена |
| PowerShell scripts | Усі пройшли синтаксичний розбір |

Початкову причину старого пропущеного logon точно не встановлено: історичного підтвердження старту / crash бракувало. Під час перевірок виявлена відмінність між вмістом AppData, видимим із інструментального процесу, та контекстом задачі. Тому міграція й перевірка виконуються через runtime IPC, а `diagnostics` читає файл / журнал від імені самого агента. Фактична повторна загрузка налаштувань через задачу перевірена; це сильніше за перевірку лише існування JSON або PID.

## Ресурси

Без примусового очищення working set. CPU — різниця `TotalProcessorTime`, інтервал 60 с, 16 логічних процесорів. МіБ = 1024² байтів; working set включає спільні сторінки, private commit — окрема метрика, не додаток до working set.

| Сценарій | Середній working set | Private commit | CPU одного ядра / всього ПК |
|---|---:|---:|---:|
| Фінальна встановлена збірка, заповнення ARGB + статична GPU, меню закрите | 14,7 МіБ | 2,7 МіБ | 0,000% / 0,000% у цьому інтервалі |
| Native, обидва виходи статичні, меню закрите | 14,8 МіБ | 2,6 МіБ | 0,000% / 0,000% |
| Відкрите меню, додатково до агента, короткий lifecycle-тест | TUI ~8,4 МіБ + conhost ~13,3 МіБ | Не вимірювався окремо | Не вимірювався за 60 с |

Числа можуть змінюватися через драйвер / анімацію / кеш ОС. Нуль CPU означає, що приріст у конкретному інтервалі нижчий за дискретність обліку Windows; анімація працювала. Попередній хвилинний інтервал установленої версії дав 14,8 МіБ та 0,052% одного ядра / 0,003% усього ПК. Старі приблизно 80 МБ — повідомлення користувача, не одночасний A/B benchmark. OpenRGB не входить у native замір і не працює у фінальному стані. SDK з активним сервером потрібно рахувати як суму ресурсів обох програм; повний performance benchmark із реальними сторонніми пристроями не виконаний.

Локальні сирі результати: `local/native-resources-final.json`, `local/native-resources-static.json`, `local/native-final-menu-lifetime.json`, `local/native-final-diagnostics.json`, `local/sdk-real-status.json`. Вони містять локальні шляхи / PID і не включаються у portable ZIP.

Фінальний EXE: 1 773 568 байтів, SHA-256 `372FDB5A747187ECEB78266E05C84A4CDB84CE536C7D5378BCA990390B384E93`. Portable ZIP містить лише EXE, інструкцію й три ліцензійні файли; список вмісту перевірений. Збірка та встановлений EXE мають однаковий hash.

## Межі перевірки

- Реальний наступний logon / reboot, sleep/resume, довга робота та unplug/replug користувачеві ще потрібно перевірити фізично. Код обробників є; ці сценарії не видаються за пройдені end-to-end тести.
- Recovery перевірено через власну fatal-подію. Реальний Windows access violation / WER event 1000 навмисно не викликався. `End task` без crash-події не перезапускається. Вимкнена задача не забезпечує recovery.
- MSI HID API синхронний: специфічне зависання драйвера всередині Windows-виклику не лікується користувацьким таймером. Під час тестів таких зависань не було.
- OpenRGB не є одноразовим експортером драйверів. Для SDK-контролерів сервер потрібен постійно; клієнт не може запобігти його власному startup scan. Підтримка залежить від конкретного контролера та software/direct mode. TCP send не є апаратним readback, а custom mode може змінити режим усього контролера, включно з невибраними зонами. Resize зон / запис firmware / flash не реалізовані.
- Razer відсутня, точна модель VIA-клавіатури не встановлена. Жодної заяви про фізично перевірену сумісність цих пристроїв немає. Незалежний lightbar залежить від того, які зони експонує OpenRGB / firmware.
- Програма не підписана цифровим сертифікатом. Нативна підтримка обмежена перевіреними моделями, без небезпечного розширення allowlist на цілий бренд.

У межах перевірених сценаріїв невиправлених блокувальних помилок не виявлено. Для ширшої сумісності наступний корисний крок — тестування конкретних підключених Razer / клавіатури через SDK та звичайного наступного входу у Windows.
